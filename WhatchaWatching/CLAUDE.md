# Web app (`WhatchaWatching`)

Blazor UI and `Program.cs`. Rules for this folder; the repo-wide ones are in the root [CLAUDE.md](../CLAUDE.md).

- **Render mode**: only `AddInteractiveServerComponents()` is registered (Blazor Server, SignalR circuit, no WebAssembly project). `App.razor` renders every page interactively (with prerendering) except pages marked `@attribute [ExcludeFromInteractiveRouting]` (Login, Register, Account, Error): those are rendered by the server only, because they set or read the auth cookie, which a circuit cannot do. Components shared by both kinds (layout, navbar) must not need interactivity: the navbar uses plain links, a GET form, `<details>` and a checkbox. Pages load data only when `RendererInfo.IsInteractive`, so the prerender shows a skeleton instead of calling services twice.
- **Accounts**: Identity (cookies) is set up in `Program.cs`, with `UserEntity` from Infrastructure (the one place the web project uses an Infrastructure type). `ICurrentUser` (Application) gives the signed-in user id; `[Authorize]` pages redirect anonymous visitors to `/login?returnUrl=...`; sign-out is a POST to `/logout`. Return urls go through `LocalUrl.Normalize` (open-redirect protection).
- **Language**: the interface is in English or French. The English text is the key (`L["..."]` with `ILocalizer`, `Loc.T` in static helpers), `Services/Localization/FrenchTranslations.cs` holds the French; a text without a translation shows in English, and `LocalizationTests` fails if a text the UI writes has none (the `/add-translation` skill fills them in). The language is the cookie set by `GET /language?culture=fr&returnUrl=...` (the footer links), else the `Accept-Language` of the browser, else English (`UseRequestLocalization`; the circuit takes it from the same request). Validation messages, Identity errors and the account emails go through the same localizer. Only the interface is translated: titles, synopses and genre names come from the providers in English. The TMDB attribution sentence stays in English on purpose, as TMDB requires its wording.
- **Security**: `Program.cs` reads the headers of the proxy first (`ProxyHeaders`: AlwaysData ends TLS, so without them the app takes every visit for http), then sets the security headers and the content security policy (`SecurityHeaders`, set when the response starts because the antiforgery token writes its own), then the rate limits (`RateLimiting`: 10 posts in 5 minutes to log in, sign-up, reset and account pages, 600 other requests a minute, by address). The antiforgery and sign-in cookies follow the scheme of the request. A circuit rechecks the security stamp every 10 minutes (`IdentityRevalidatingAuthenticationStateProvider`), so a changed password or a deleted account ends open sessions. Account emails (`Services/Email`: `IAccountEmailService`, `IEmailTransport`) never say whether an address has an account. Operational steps are in [docs/OPERATIONS.md](../docs/OPERATIONS.md). Use the `security-reviewer` agent after changing any of this.
- **Component tree**: `Components/App.razor` → `Routes.razor` (Router, `NotFoundPage` = `Pages.NotFound`) → `Layout/MainLayout.razor` → pages in `Components/Pages/`. Shared `@using`s go in `Components/_Imports.razor`.
- **Errors**: outside Development, `/Error` + HSTS. `UseStatusCodePagesWithReExecute("/not-found")` backs the `NotFound` page.
- **Styling**: no CSS framework. Design tokens (palette, radii, fonts) are CSS variables in `wwwroot/app.css`, which also holds the shared classes (`.btn`, `.input`, `.card`, `.anime-grid`...). Components use CSS isolation (`*.razor.css`). `ReconnectModal` has a collocated `.razor.js`.
- **Static assets**: `app.MapStaticAssets()`, not `UseStaticFiles`.
- **Site icon**: `wwwroot/favicon.svg` (a pink die on the dark tile of the site, its middle pip an amber play button: the random pick of what to watch; the source of the other files), `favicon.png` (48 px, fallback) and `apple-touch-icon.png` (180 px, opaque, for home screens), declared in `App.razor`. The PNGs are drawings of the SVG: redo them when the SVG changes.
- **Version**: `<Version>` in `WhatchaWatching.csproj` (raised by the `/commit-push` skill from what the commit changes: `feat` is a minor bump, `fix` and the like a patch, docs/tests/tooling alone none; it can also be raised by hand). The footer shows it with the short commit the SDK adds to the informational version at build time (`AppVersion`), so a deployment can be told apart from the previous one. The commit is the one checked out when building: build from a clean, committed tree.
- Blazor components never touch `DbContext` or HTTP clients directly: they call Application services through their interfaces.
